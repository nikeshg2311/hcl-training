\# JFS-27 - User Stories



\## Project



IT Helpdesk \& Service Desk Ticketing



\## Agile User Stories



\### US01 - Create IT Ticket



\*\*FR:\*\* FR1



\*\*User Story:\*\*



As an Employee, I want to create an IT ticket and attach a screenshot,

so that I can clearly report my technical issue.



\*\*Story Points:\*\* 3



\*\*Acceptance Criteria:\*\*



\- Employee can enter ticket details.

\- Employee can select category and priority.

\- Employee can attach a supported screenshot.

\- Ticket is created successfully.

\- Employee receives a ticket ID.



\---



\### US02 - Automatic Ticket Assignment



\*\*FR:\*\* FR2



\*\*User Story:\*\*



As an Employee, I want my ticket to be automatically assigned to the

appropriate support group, so that my issue reaches the correct team

without manual intervention.



\*\*Story Points:\*\* 5



\*\*Acceptance Criteria:\*\*



\- System identifies the appropriate support group.

\- Ticket is assigned automatically.

\- Assignment is recorded.

\- Assigned group can view the ticket.



\---



\### US03 - Manage Ticket



\*\*FR:\*\* FR3



\*\*User Story:\*\*



As an Agent, I want to update the ticket status, priority, and add notes,

so that I can accurately track and manage the issue.



\*\*Story Points:\*\* 3



\*\*Acceptance Criteria:\*\*



\- Agent can change ticket status.

\- Agent can change ticket priority.

\- Agent can add comments.

\- Agent can add internal notes.

\- Internal notes are not visible to the requester.



\---



\### US04 - SLA Tracking



\*\*FR:\*\* FR4



\*\*User Story:\*\*



As a Team Lead, I want the system to track SLA timers and flag SLA

breaches, so that I can take action before or when service commitments

are missed.



\*\*Story Points:\*\* 5



\*\*Acceptance Criteria:\*\*



\- SLA starts when the ticket is created.

\- SLA is calculated according to ticket priority.

\- Non-working hours are excluded.

\- SLA breach is detected.

\- Breached tickets are clearly flagged.



\---



\### US05 - Reassign Ticket



\*\*FR:\*\* FR5



\*\*User Story:\*\*



As a Team Lead, I want to reassign tickets between agents, so that

tickets can be distributed according to workload and availability.



\*\*Story Points:\*\* 3



\*\*Acceptance Criteria:\*\*



\- Team Lead can view assigned tickets.

\- Team Lead can select another agent.

\- Ticket assignment is updated.

\- Assignment history is maintained.



\---



\### US06 - Knowledge Base Article



\*\*FR:\*\* FR6



\*\*User Story:\*\*



As an Agent, I want to link relevant Knowledge Base articles to tickets,

so that I can provide users with useful troubleshooting information.



\*\*Story Points:\*\* 3



\*\*Acceptance Criteria:\*\*



\- Agent can search Knowledge Base articles.

\- Agent can select a relevant article.

\- Article can be linked to the ticket.

\- Requester can access the linked article where applicable.



\---



\### US07 - Reopen Resolved Ticket



\*\*FR:\*\* FR7



\*\*User Story:\*\*



As an Employee, I want to reopen a resolved ticket within three days,

so that I can report that the issue has returned or was not completely

resolved.



\*\*Story Points:\*\* 3



\*\*Acceptance Criteria:\*\*



\- Employee can reopen a resolved ticket.

\- Reopening is allowed only within three days.

\- Reopened ticket returns to an active state.

\- Reopening after three days is rejected.



\---



\### US08 - Agent Performance Metrics



\*\*FR:\*\* FR8



\*\*User Story:\*\*



As a Team Lead, I want to view agent performance metrics, so that I can

monitor workload, resolution performance, and SLA compliance.



\*\*Story Points:\*\* 5



\*\*Acceptance Criteria:\*\*



\- Team Lead can view agent ticket counts.

\- Team Lead can view resolved tickets.

\- Team Lead can view SLA performance.

\- Team Lead can view resolution metrics.

\- Metrics are restricted to authorized users.
